FIX: Root Cause Analysis: Why was the data missing/statistics gone?
When we secured the /alumni/ backend endpoints (as requested by the task requirements), we added a centralized verify_token middleware. Two separate issues prevented the alumni data and statistics from loading:

Frontend Request Race Condition:
The Issue: When the frontend dashboard page loaded, it immediately dispatched loadAlumni() and loadCount() requests to the backend. At the exact same moment, it began an asynchronous process (checkAuth()) to extract the user's login token from storage and set it in the Axios request headers.
The Consequence: Because checkAuth() was asynchronous, the initial requests to the gated /alumni/ endpoints were sent before the authorization token was set. The backend rejected these request with a 401 Unauthorized response. Once the token was loaded, the frontend did not retry the failed requests, leaving the dashboard blank.
JWT Secret Mismatch:
The Issue: The central Auth Module (located at automatic-certify-appointee.ngrok-free.dev) signs SSO login tokens using a private secret key. Our local backend verified signatures using a default local key ("shared-secret-key-123").
The Consequence: Even after the frontend passed the token correctly, the signatures did not match. The backend threw a Signature verification failed error and returned 401 Unauthorized.
2. Solutions Implemented
A. Resolved Frontend Race Condition
File: frontend/alumni-connect-hub-main/src/components/Dashboard.tsx
Changes:
Introduced a new react state variable: authLoaded.
Updated the authorization checker hook to set authLoaded to true once it successfully finishes loading the token and setting the API authorization headers.
Deferred the execution of loadAlumni() and loadCount() until authLoaded is true. This guarantees that the frontend will never dispatch requests to gated backend endpoints until the authorization token is fully configured.
B. Unified JWT Signature Verification (Zero-Trust Remote Validation)
Files: app/utils/security.py and .env
Changes:
Configured AUTH_API_URL dynamically inside the backend's .env environment file.
Modified the verify_token middleware. When AUTH_API_URL is detected, the backend forwards the incoming token to the Auth Module's /api/auth/verify endpoint.
If the Auth Module verifies the token successfully (status 200 and valid: true), we unpack the decoded user payload and authorize the request.
If the central server is offline, the middleware gracefully falls back to local JWT signature decoding to ensure testing environments are not disrupted.
